# Product Veda · Deliverable 2 — Animation System

**Authoritative.** Every deliverable that moves, glows, pulses, or breathes
references this document. No duration, easing, colour, or particle parameter
may be invented outside of `00_TOKENS.md` and this file.

Two engineers reading this document must produce the same visual output for
the same seed. Ambiguity is a bug.

---

## 2.0 · Governing constraints (read before implementing anything)

1. **Real state drives animation.** No animation may be driven by a timer that
   invents liveness. The idle breathe and the pulse are the sole exceptions;
   they represent a genuine resting heartbeat, not activity.
2. **Nothing bounces. Nothing spins.** Overshoot ≤ 3% and only in two named
   places: decision-settle and celebration bloom (both called out explicitly
   below). Every other motion ends at its target value.
3. **`prefers-reduced-motion` is a designed state.** Every animation in this
   document has a named static endpoint. The tree renders fully grown and still;
   state is carried by colour and particle density only.
4. **60 fps on integrated graphics.** Section 2.4 is the performance contract.
5. **Determinism rule.** A given founder seed always produces the same tree
   geometry. The seed is a 32-bit unsigned integer derived from the founder's
   unique ID (implementation detail of the runtime; this document only requires
   that the seed be stable across sessions for the same founder).

## 2.1 · Tree geometry and construction

### 2.1.1 Normalised coordinate space

All geometry is computed in a unit space where:

- Origin `(0, 0)` = trunk base
- `+y` = upward
- `x` ranges from approximately `−0.5` to `+0.5` at the widest canopy extent

The trunk base maps to canvas coordinates as defined in `01_FOUNDER_SURFACE
§1.2`:

```
canvasX = 0.5 × W
canvasY = 1.06 × H          // deliberately below the bottom edge
```

The normalised `y = 1.0` corresponds to `canvasY = 0.16 × H` (canopy ceiling).
Thus the vertical scale factor is:

```
scaleY = (1.06 × H) − (0.16 × H) = 0.90 × H   // normalised 1 unit = 0.90 × H px
```

The horizontal scale factor equals `scaleY` (uniform, square aspect). The
canopy width is clamped per `01_FOUNDER_SURFACE §1.2`:

```
maxCanopyPx = min(0.62 × W, 900)  // desktop
             min(0.70 × W, 900)  // laptop
             min(0.86 × W, 900)  // tablet
```

### 2.1.2 Recursive branching

The tree is generated by a seeded pseudo-random number generator
(xorshift32 with the founder seed). Branch generations are numbered 0–5.
Generation 0 is the trunk.

| Generation | Name | Branch count from parent | Length ratio | Angle spread | Segment count | Tip thickness (px) | Base thickness (px) |
|---|---|---|---|---|---|---|---|
| 0 | Trunk | 1 (single) | 1.0 (full height) | 0° | 12 | 3.2 | 5.5 |
| 1 | Primary | 2 | 0.62 | ±22° – ±34° | 8 | 2.0 | 3.2 |
| 2 | Secondary | 2 | 0.58 | ±18° – ±30° | 6 | 1.2 | 2.0 |
| 3 | Tertiary | 2 | 0.54 | ±16° – ±28° | 5 | 0.7 | 1.2 |
| 4 | Quaternary | 2 | 0.50 | ±14° – ±26° | 4 | 0.4 | 0.7 |
| 5 | Canopy tips | 2 | 0.44 | ±12° – ±24° | 3 | 0.15 | 0.4 |

**Angle spread interpretation.** Each generation row lists a range, e.g.
`±22° – ±34°`. The actual half-angle for any given split is drawn from
`seededRandom() × (34 − 22) + 22` degrees, independently for left and right
children. The sign is fixed: left child is negative (leftward), right child is
positive (rightward), before the parent's own orientation is applied.

**Trunk.** Generation 0 grows straight: its direction is exactly `+y` in
normalised space (straight up). Its base is at `(0, 0)` and its tip is at
`(0, 0.44)`, giving room for the canopy above.

**Spawn point.** Each parent branch spawns its two children at a point
`0.72 × length` up from its base (not at the tip). This produces a more
natural fork with a short continuing segment above the split.

**Taper.** Thickness decreases linearly from base to tip within each segment.
At the junction point where children spawn, the parent's thickness at that
height becomes the children's base thickness (already specified in the table
above; the table values are targets at generation boundaries, not hard
overrides — the linear taper within each generation is continuous).

**Total branch count.** With 2 children per parent starting from 1 trunk, the
theoretical maximum is 1 + 2 + 4 + 8 + 16 + 32 = 63 branches. In practice
some branches are culled when their normalised tip position would fall outside
`y > 0.95` or `|x| > 0.52`; this is a hard clip, not a soft fade.

### 2.1.3 Particle assignment

Particles are distributed along branch positions, with jitter that increases
toward the canopy.

**Position sampling.** For each branch of generation `g`, sample positions
uniformly along the branch length. The number of positions sampled per branch
is proportional to that branch's length in normalised units × the per-generation
density factor below:

| Generation | Density factor (particles / normalised-unit length) |
|---|---|
| 0 (trunk) | 18 |
| 1 | 24 |
| 2 | 32 |
| 3 | 42 |
| 4 | 58 |
| 5 | 80 |

This concentrates particles in the canopy, which is perceptually correct.

**Particle count budgets.** Total across all branches, after culling:

| Breakpoint | Budget |
|---|---|
| Desktop (≥ 1440) | 2400 |
| Laptop (1180 – 1439) | 1800 |
| Tablet (834 – 1179) | 1200 |

If the raw density calculation yields more than the budget, reduce density
factors uniformly (multiply all by `budget / rawCount`) and resample. If it
yields fewer, increase only generation-4 and generation-5 density.

**Jitter.** Each particle's rest position is displaced from its branch-sampled
position by a jitter vector drawn from a 2D Gaussian with σ = `jitterSigma(g)`:

| Generation | `jitterSigma(g)` (normalised units) |
|---|---|
| 0 | 0.003 |
| 1 | 0.006 |
| 2 | 0.010 |
| 3 | 0.016 |
| 4 | 0.024 |
| 5 | 0.034 |

The jitter vectors are baked at tree construction time (same seed ⇒ same
jitter). They do not change at runtime; only the particles' animated offsets
from their rest positions change.

### 2.1.4 Particle visual properties

Each particle is a filled circle on the canvas. Per-particle properties are
baked at construction time:

| Property | Value |
|---|---|
| Base radius | `0.8 + seededRandom() × 1.4` px (before DPR scale) |
| Base alpha | `0.40 + seededRandom() × 0.45` |
| Alpha oscillation amplitude | `0.05 + seededRandom() × 0.12` |
| Alpha oscillation period | `3200 + seededRandom() × 4800` ms |
| Alpha oscillation phase | `seededRandom() × 2π` rad (independent per particle) |

The alpha oscillation is a pure sine: `α(t) = baseAlpha + amplitude × sin(2π × t / period + phase)`.

The oscillation is **always active** regardless of tree state. It is the
particle's individual breath. It is suppressed only by `prefers-reduced-motion`.

**Colour.** All particles use `--tree-particle` by default. Celebration
introduces `--tree-bloom` (see §2.2.6). The trunk (generation 0) particles use
`--tree-core` at full alpha to suggest a denser core.

### 2.1.5 Filament lines

Filaments are thin line segments connecting nearby particles to suggest
branching structure. They are drawn **under** the particles (drawn first in
each frame).

**Connection rule.** For each particle `A`, connect to particle `B` if:
- `B` is on the same branch or a direct parent/child branch of `A`'s branch
- The normalised distance `|A − B|` ≤ 0.045
- At most 3 filaments per particle (closest neighbours first)

**Visual properties:**
```
strokeStyle: var(--tree-filament)    // rgba(127,211,255,0.10) dark / rgba(28,127,184,0.14) light
lineWidth:   0.6px
globalAlpha: computed per-frame from the two particles' current alphas: min(αA, αB) × 0.65
```

Filaments do not animate independently; their alpha is derived entirely from
the particles they connect.

### 2.1.6 Determinism guarantee

```
// Pseudocode — the shape of the seeded-random dependency
function buildTree(founderSeed: uint32): TreeData {
  const rng = xorshift32(founderSeed)
  // All calls to rng() happen in a fixed, deterministic order.
  // No Date(), no Math.random(), no crypto.getRandomValues() inside buildTree.
  ...
}
```

The `xorshift32` algorithm:
```js
function xorshift32(seed) {
  let s = seed >>> 0
  return function () {
    s ^= s << 13; s ^= s >>> 17; s ^= s << 5
    return (s >>> 0) / 0xFFFFFFFF
  }
}
```

The tree data structure (branch endpoints, particle rest positions, per-particle
baked properties) is computed once at startup and cached. It is never
recomputed unless the window resizes beyond a breakpoint boundary.

## 2.2 · The six states

Each state section contains:
1. **Founder perception** — one sentence describing the phenomenological
   experience, written as the reference for whether an implementation is correct.
2. **Parameter table** — exact values an engineer copies.
3. **Entry/exit transitions** — from/to any other state.
4. **`prefers-reduced-motion` static endpoint.**

### Common parameter definitions used across all tables

| Parameter name | Meaning |
|---|---|
| `breatheAmp` | Peak scale deviation from 1.0; tree canvas CSS `scale(1 + breatheAmp)` and `scale(1 − breatheAmp)` at the extremes of the breathe cycle |
| `breathePeriod` | Full period of one breathe cycle in ms |
| `breatheEasing` | Token used for each half-cycle |
| `bloomOpacity` | The `.bloom` element's CSS `opacity` |
| `bloomToken` | Colour token for the bloom radial-gradient centre stop |
| `bloomAlpha` | The alpha value of the bloom centre stop |
| `bloomTransDuration` | Token governing bloom opacity transitions |
| `driftMul` | Multiplier on per-particle idle drift amplitude (baseline 1.0) |
| `seekStiffness` | Spring stiffness for particle return to rest position; unitless [0.01–0.12] |
| `pulseDir` | Direction of pulse travel: `UP` or `DOWN` (from trunk base to canopy, or reverse) |
| `pulsePeriod` | One full pulse cycle in ms |
| `pulseCrest` | Brightness multiplier at pulse wavefront (1.0 = no change; max 1.6) |
| `colour` | Primary tree colour token for this state |

### 2.2.1 Idle

**Founder perception:** The tree rests in a calm, living stillness — present
but unhurried, like breathing in a quiet room.

| Parameter | Value |
|---|---|
| `breatheAmp` | 0.006 |
| `breathePeriod` | 6400 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 0.60 |
| `bloomToken` | `--s-live` |
| `bloomAlpha` | 0.055 |
| `bloomTransDuration` | `--d-8` |
| `driftMul` | 1.0 |
| `seekStiffness` | 0.02 |
| `pulseDir` | UP |
| `pulsePeriod` | 8000 ms |
| `pulseCrest` | 1.08 |
| `colour` | `--tree-particle` |

**Particle drift.** Each particle drifts from its rest position by a slowly
evolving 2D Perlin offset. The Perlin field is sampled at
`(restX + t × 0.000024, restY + t × 0.000031)` — different rates on each
axis so the motion is not perfectly circular. The peak-to-peak drift amplitude
is `driftMul × jitterSigma(g) × 0.7` normalised units, where `g` is the
particle's generation. Trunk particles barely move; canopy tips drift gently.

**Filament behaviour.** Connections are stable in Idle. Line alpha varies only
as the connected particles' alphas vary via their individual oscillations.

**Entry from any state:** `--d-8` `--e-settle` on all parameters. Bloom
opacity transitions first, then breathe amplitude settles over the same
duration.

**Exit to any state:** `--d-8` `--e-settle` unless overridden in the
destination state's entry specification.

**`prefers-reduced-motion` endpoint:** Tree fully grown, particles static at
rest positions, no breathe, no drift, no pulse. Bloom at opacity 0.60, static.
Filaments static at computed alphas.

### 2.2.2 Listening

**Founder perception:** The tree sharpens its attention — a soft, inward
gathering, as if the whole canopy is leaning in to hear.

| Parameter | Value |
|---|---|
| `breatheAmp` | 0.010 |
| `breathePeriod` | 4200 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 1.0 |
| `bloomToken` | `--s-live` |
| `bloomAlpha` | 0.055 |
| `bloomTransDuration` | `--d-8` |
| `driftMul` | 0.55 |
| `seekStiffness` | 0.045 |
| `pulseDir` | DOWN |
| `pulsePeriod` | 4800 ms |
| `pulseCrest` | 1.20 |
| `colour` | `--tree-particle` |

**Particle behaviour.** Drift amplitude is reduced (`driftMul` 0.55) because
the tree is attending, not wandering. Seek stiffness increases, so particles
hold closer to their rest positions — the canopy appears to tighten.

**Directional flow.** A very slow downward bias is applied: each particle's
Perlin drift field has an additional `−0.00004` per-frame offset on the
normalised `y` axis (downward in canvas coordinates, toward the founder). This
must be subtle — the motion is felt, not watched.

**Filament behaviour.** Filaments brighten slightly: their base alpha
multiplier rises from 0.65 (Idle) to 0.80 over `--d-8`.

**Pulse direction DOWN** means the pulse wavefront travels from canopy tip
toward trunk base — a sense of receiving, gathering inward.

**Entry from Idle:** `--d-8` `--e-settle`. Breathe period shortens, bloom
lifts to 1.0 opacity, seek stiffness tightens. These all interpolate
simultaneously; no sequencing.

**Entry from any other state:** same as from Idle.

**Exit to Idle:** `--d-8` `--e-settle`.

**`prefers-reduced-motion` endpoint:** Tree static, bloom at opacity 1.0 with
`--s-live` colour. No motion. State label "LISTENING" visible in mic component.

### 2.2.3 Thinking

**Founder perception:** The tree glows with a different quality of light —
inward, concentrating, as if processing is visible in the density of the
branches.

| Parameter | Value |
|---|---|
| `breatheAmp` | 0.008 |
| `breathePeriod` | 5200 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 0.85 |
| `bloomToken` | `--s-live` |
| `bloomAlpha` | 0.065 |
| `bloomTransDuration` | `--d-8` |
| `driftMul` | 1.4 |
| `seekStiffness` | 0.014 |
| `pulseDir` | UP |
| `pulsePeriod` | 3600 ms |
| `pulseCrest` | 1.35 |
| `colour` | `--tree-particle` |

**Particle behaviour.** Drift multiplier increases to 1.4 and seek stiffness
decreases, so particles have slightly more freedom — the canopy shimmers. The
Perlin field is sampled at a faster time coefficient:
`(restX + t × 0.000052, restY + t × 0.000061)` — roughly 2× the Idle rate.
The increase in motion should read as internal activity, not agitation.

**Pulse.** The pulse crest is the brightest of any non-celebration state
(1.35). It travels upward (UP) at `pulsePeriod` 3600 ms — faster than Idle,
which reads as engagement. Pulse wavefront width: 18% of normalised tree
height.

**Filament behaviour.** Filament alpha multiplier rises to 0.90 in Thinking.
Branches appear more defined when the tree is working.

**Branch micro-movement.** The breathe scale transform is applied with a
slight asymmetry: the x-axis breathe amplitude is `breatheAmp × 0.6` while
the y-axis amplitude is `breatheAmp × 1.0`. This creates a very subtle
vertical pulse in preference to horizontal. Both axes use `--e-breathe`.

**Entry from Listening:** `--d-8` `--e-settle`. Pulse period decreases (speeds
up), drift increases, bloom adjusts.

**Entry from Idle:** `--d-8` `--e-settle`.

**Entry from Speaking:** `--d-8` `--e-settle`.

**Exit to any state:** `--d-8` `--e-settle`.

**`prefers-reduced-motion` endpoint:** Tree static, bloom at opacity 0.85.
Particles at slightly higher density alpha (the `bloomAlpha` 0.065 implies
a marginally brighter canopy). No motion.

### 2.2.4 Speaking

**Founder perception:** The tree speaks in warmth — its pulse is the voice,
and the light rises and falls exactly as Somesh talks.

| Parameter | Value |
|---|---|
| `breatheAmp` | `0.006 + voiceEnvelope × 0.018` (see voice binding below) |
| `breathePeriod` | 3200 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 1.0 |
| `bloomToken` | `--s-live` |
| `bloomAlpha` | `0.050 + voiceEnvelope × 0.030` |
| `bloomTransDuration` | `--d-4` (faster response during speech) |
| `driftMul` | `0.8 + voiceEnvelope × 0.6` |
| `seekStiffness` | 0.032 |
| `pulseDir` | UP |
| `pulsePeriod` | `2800 − voiceEnvelope × 800` ms (louder = faster; floor 2000 ms) |
| `pulseCrest` | `1.15 + voiceEnvelope × 0.30` (max 1.45) |
| `colour` | `--tree-particle` |

#### Voice amplitude binding

The voice pipeline exposes a continuous `rawAmplitude` value in `[0, 1]`
representing the RMS envelope of Somesh's output audio at the current instant.

**Smoothing.** Apply a one-pole low-pass filter every animation frame:

```js
const SMOOTH = 0.82   // smoothing coefficient — do not tune without A/B test
voiceEnvelope = voiceEnvelope × SMOOTH + rawAmplitude × (1 − SMOOTH)
```

This gives a time constant of approximately `−frameDt / ln(SMOOTH)` ≈ 90 ms
at 60 fps. The smoothing is intentionally asymmetric in practice: use
`SMOOTH = 0.82` for both rise and fall. Do not use separate attack/release
coefficients — the symmetry is deliberate.

**Mapping.** The smoothed `voiceEnvelope` (0–1) is used directly in all
parametric expressions in the table above. It scales `breatheAmp`,
`bloomAlpha`, `driftMul`, and `pulseCrest` in proportion to how energetically
Somesh is speaking.

**Fallback when no amplitude data exists.** When the voice pipeline does not
provide `rawAmplitude` (e.g. synthesised voice without envelope extraction),
the system uses a fixed `voiceEnvelope = 0.55`. This value is constant — it
produces a credible mid-energy Speaking state. **A random or oscillating
fallback is forbidden.** The 0.55 constant must be named in code:

```js
const FALLBACK_VOICE_ENVELOPE = 0.55
```

**Filament behaviour.** Filament alpha multiplier is `0.75 + voiceEnvelope × 0.15`.
Filaments brighten with the voice.

**Entry from Thinking:** `--d-5` `--e-settle`. Faster entry because speaking
follows thinking without pause.

**Entry from Listening:** `--d-6` `--e-settle`.

**Entry from Idle:** `--d-8` `--e-settle`.

**Exit to Thinking:** `--d-6` `--e-settle`. Voice envelope is set to 0
immediately on exit; the speaking parameters decay via the transition.

**Exit to Idle:** `--d-8` `--e-settle`.

**`prefers-reduced-motion` endpoint:** Tree static, bloom at opacity 1.0 with
the bloom gradient using `bloomAlpha = 0.050 + 0.55 × 0.030 = 0.0665` (the
fallback envelope). No motion. The waveform icon in the mic button becomes the
static 3-bar level meter specified in `00_TOKENS §10.10`.

### 2.2.5 Waiting / Attention

**Founder perception:** The tree becomes gently present — a warm, patient
signal that something requires the founder's hand, expressed without urgency or
alarm.

| Parameter | Value |
|---|---|
| `breatheAmp` | 0.007 |
| `breathePeriod` | 5800 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 0.70 |
| `bloomToken` | `--s-attend` |
| `bloomAlpha` | 0.045 |
| `bloomTransDuration` | `--d-8` |
| `driftMul` | 0.9 |
| `seekStiffness` | 0.025 |
| `pulseDir` | UP |
| `pulsePeriod` | 7200 ms |
| `pulseCrest` | 1.12 |
| `colour` | `--tree-particle` |

**Colour.** The bloom hue shifts from `--s-live` to `--s-attend`
(`#FFB454` dark / `#B87309` light). This is the primary state signal. The
particle colour remains `--tree-particle` — only the bloom hue changes, not
the particles themselves. Do not tint the particles amber.

**Pulse.** The longer period (7200 ms) and low crest (1.12) keep the pulse
calm. The point of this state is that the tree is present and patient, not
demanding. The amber bloom glow is enough; the motion should not amplify it.

**Filament behaviour.** Filament alpha multiplier 0.70 (slightly dimmer than
Idle). The slight withdrawal supports the amber shift as a gentle signal rather
than an alarm.

**The hard constraint for this state:**
> This state must never read as aggressive, alarming, or urgent. Any
> implementation that makes the tree appear to flash, strobe, or rapidly
> pulse is a bug. The parameter values above are the ceiling — do not increase
> `pulseCrest` or decrease `pulsePeriod` in this state.

**Entry from Idle:** `--d-8` `--e-settle`. The bloom hue shift happens at the
full `--d-8` duration — colour changes slowly so the shift is felt before it is
noticed.

**Entry from Speaking:** `--d-8` `--e-settle`. A speaking state interrupted by
an attention event uses Speaking's parameters until the transition completes.
**State priority rule: Speaking takes precedence over Waiting.** The Waiting
state only becomes visible once Speaking ends.

**Entry from Thinking:** `--d-8` `--e-settle`.

**Exit to any state:** `--d-8` `--e-settle`. Bloom hue returns to `--s-live`
as part of the transition.

**`prefers-reduced-motion` endpoint:** Tree static, bloom at opacity 0.70 with
`--s-attend` hue and 0.045 alpha. No motion. The amber bloom is the entire
signal. The notification component (D5) also shows the verbal description.

### 2.2.6 Celebration

**Founder perception:** The tree opens, briefly and completely, into gold — a
moment of genuine recognition, not fanfare.

| Parameter | Value |
|---|---|
| `breatheAmp` | 0.018 (peak, then decays — see sequence below) |
| `breathePeriod` | 2800 ms |
| `breatheEasing` | `--e-breathe` |
| `bloomOpacity` | 1.0 |
| `bloomToken` | `--s-bloom` |
| `bloomAlpha` | 0.075 |
| `bloomTransDuration` | `--d-6` |
| `driftMul` | 2.2 (peak) |
| `seekStiffness` | 0.008 (peak) |
| `pulseDir` | UP |
| `pulsePeriod` | 2200 ms |
| `pulseCrest` | 1.55 |
| `colour` | `--tree-bloom` (gold, transient) |

**Restraint rules — these are hard limits, not suggestions:**

1. Celebration fires only when the runtime delivers a real founder-facing
   completion event. It is never triggered on app open, on startup, or on any
   system event that the founder did not initiate.
2. It fires at most once per distinct event. Duplicate events within 400 ms are
   de-duplicated; only the first fires.
3. `--tree-bloom` particles are a subset of the existing particle set — there is
   no particle count uplift that adds new particles. Instead, a fraction of
   existing particles cross-fade their colour from `--tree-particle` to
   `--tree-bloom`. The fraction is `0.35` (35% of all particles).
4. The gold is introduced and retired gracefully. See the sequence table below.

**Celebration sequence (t = 0 at event trigger):**

| t (ms) | Action |
|---|---|
| 0 | Enter Celebration state; begin bloom hue transition `--s-live` → `--s-bloom` over `--d-6` |
| 0 – 600 | Bloom opacity 0.85 → 1.0 over `--d-6` `--e-settle` |
| 0 – 600 | 35% of particles begin colour cross-fade `--tree-particle` → `--tree-bloom` over `--d-6` `--e-settle`; particles selected by descending generation (canopy tips first) |
| 0 – 600 | `driftMul` 1.0 → 2.2 over `--d-6` `--e-settle`; `seekStiffness` 0.02 → 0.008 |
| 0 – 600 | `breatheAmp` 0.006 → 0.018; a single breathe-out to the expanded scale (overshoot at `+3%` of 0.018 = 0.00054; this is the one permitted overshoot for celebration) |
| 600 – 2800 | Hold peak: gold particles, bright bloom, wide breathe |
| 2800 – 4400 | Decay: particles cross-fade `--tree-bloom` → `--tree-particle` over `--d-8` `--e-settle` |
| 2800 – 4400 | `driftMul` 2.2 → 1.0; `seekStiffness` 0.008 → 0.02; `breatheAmp` 0.018 → 0.006 |
| 2800 – 4400 | Bloom hue `--s-bloom` → `--s-live` over `--d-8` `--e-settle` |
| 4400 | Celebration ends; state transitions to Idle |

**Total celebration duration: 4400 ms.** This is a hard maximum; the runtime
must not extend or repeat it.

**Entry.** Celebration may be entered from any state. The transition always
uses the sequence above regardless of prior state.

**Exit.** Only to Idle. The post-celebration Idle uses normal Idle parameters.

**Filament behaviour.** During celebration, filament alpha multiplier peaks at
1.0 (fully opaque baseline). Gold particles connected by filaments make the
branching structure briefly and beautifully visible.

**`prefers-reduced-motion` endpoint:** A single `--d-3` (240 ms) colour shift
of the bloom from `--s-live` to `--s-bloom` at opacity 1.0, then
`--d-8` return to Idle. No particle colour change. No motion. Duration maximum:
240 + 1400 = 1640 ms total.

## 2.3 · State machine

### 2.3.1 Complete transition table

Rows are the **from** state; columns are the **to** state. Cell format:
`duration-token` + `easing-token`. Where a cell says "via" an intermediate
state is briefly held.

|  | → Idle | → Listening | → Thinking | → Speaking | → Waiting | → Celebration |
|---|---|---|---|---|---|---|
| **Idle →** | — | `--d-8` `--e-settle` | `--d-8` `--e-settle` | `--d-8` `--e-settle` | `--d-8` `--e-settle` | `--d-6` `--e-settle` |
| **Listening →** | `--d-8` `--e-settle` | — | `--d-8` `--e-settle` | `--d-6` `--e-settle` | `--d-8` `--e-settle` | `--d-6` `--e-settle` |
| **Thinking →** | `--d-8` `--e-settle` | `--d-8` `--e-settle` | — | `--d-5` `--e-settle` | `--d-8` `--e-settle` | `--d-6` `--e-settle` |
| **Speaking →** | `--d-8` `--e-settle` | `--d-6` `--e-settle` | `--d-6` `--e-settle` | — | **deferred** (see §2.3.2) | `--d-6` `--e-settle` |
| **Waiting →** | `--d-8` `--e-settle` | `--d-8` `--e-settle` | `--d-8` `--e-settle` | `--d-6` `--e-settle` | — | `--d-6` `--e-settle` |
| **Celebration →** | `--d-8` `--e-settle` (only) | forbidden | forbidden | forbidden | forbidden | — |

**"Forbidden" exits from Celebration** mean the runtime must not send a state
change during the celebration sequence. If the runtime attempts to switch to
Listening or Thinking mid-celebration, the event is queued and fires when
celebration completes (at t = 4400 ms). There is no visual interruption.

### 2.3.2 State priority and conflict resolution

When two conditions are simultaneously true, apply the following priority
(highest first):

1. **Celebration** — if a celebration event fires, it executes regardless.
   Other states are queued.
2. **Speaking** — if Somesh is currently outputting audio, the tree is in
   Speaking. A Waiting/Attention event that arrives while Speaking is active
   does not preempt Speaking; instead, the Waiting state is entered immediately
   after Speaking ends.
3. **Listening** — if the founder is currently speaking (mic active), the tree
   is Listening. Thinking does not preempt Listening.
4. **Thinking** — active when the runtime is processing, no audio I/O active.
5. **Waiting / Attention** — active when a human-required event is pending and
   no higher-priority state is active.
6. **Idle** — the default when no other condition is true.

**Queue depth: 1.** Only one deferred state is held in the queue. If a second
deferred state arrives before the first is applied, the second replaces the
first.

### 2.3.3 Colour interpolation rule

Tree state colour transitions interpolate slowly: **2% per frame** in the
colour space of the bloom gradient. This means a bloom hue shift from
`--s-live` to `--s-attend` takes approximately 50 frames (≈ 833 ms at 60 fps)
before the human eye notices it as a colour. The purpose is that a state change
is **felt before it is noticed** — the tree shifts beneath conscious attention.

This applies to:
- `bloomToken` hue transitions
- `bloomAlpha` value transitions
- Particle colour transitions (including Celebration's gold introduction)

It does NOT apply to:
- `breatheAmp`, `breathePeriod`, `driftMul`, `seekStiffness` — these
  interpolate over the transition duration tokens specified in §2.3.1.

## 2.4 · Performance budget

### Target: 60 fps on integrated graphics

Frame-time budget: **16.67 ms per frame**. Target: ≤ 12 ms actual canvas work,
leaving 4.67 ms for JS overhead and compositing.

### Degradation ladder

Reductions are applied in order. Move to the next level only when the previous
level does not restore the target frame time. Frame time is measured as a
rolling 60-frame average using `performance.now()`.

| Level | Condition (rolling avg) | Reduction applied |
|---|---|---|
| 0 (nominal) | ≤ 12 ms | No reduction |
| 1 | 12 – 16 ms | Reduce particle count to 85% of breakpoint budget |
| 2 | 16 – 20 ms | Reduce particle count to 70%; disable filament drawing |
| 3 | > 20 ms | Reduce particle count to 50%; disable alpha oscillation (use static base alpha per particle); filaments off |

**Rule: reduce particle COUNT before reducing motion quality.** The breathing
and state transitions must remain smooth even at Level 3. Visual fidelity
degrades (fewer particles, no filaments), but motion quality does not.

**Hysteresis.** Moving from a higher level to a lower level requires the
rolling average to be below the lower level's threshold for 120 consecutive
frames (2 seconds) before recovering.

### `requestAnimationFrame` discipline

```js
// Correct pattern
let animHandle = null
function startRender() {
  if (animHandle !== null) return   // idempotent
  animHandle = requestAnimationFrame(renderLoop)
}
function renderLoop(timestamp) {
  if (!document.hasFocus() || document.hidden) {
    animHandle = null
    return   // pauses — see pause rule below
  }
  update(timestamp)
  draw()
  animHandle = requestAnimationFrame(renderLoop)
}
function stopRender() {
  if (animHandle !== null) cancelAnimationFrame(animHandle)
  animHandle = null
}
```

### Canvas clearing strategy

Each frame:
1. `ctx.clearRect(0, 0, canvas.width, canvas.height)` — full clear, no
   accumulation effects. The canvas has `alpha: true` so the `--c-void`
   background of the `.bloom` layer shows through.
2. Draw filaments (all, in one pass).
3. Draw particles (all, in one pass, sorted by generation ascending so
   generation-5 canopy particles are on top).
4. No other draw operations on the tree canvas.

### Pause rule

**The tree pauses rendering entirely when the window is unfocused or
minimised.** This is implemented via the `document.hidden` check in
`renderLoop` above and a `visibilitychange` event listener. On return to focus,
the animation resumes from the current timestamp — no jump-cut, no
catch-up. The first resumed frame uses `timestamp` directly as if no time
passed, and the breathe/pulse phases are set to their current values (not
reset).

```js
document.addEventListener('visibilitychange', () => {
  if (!document.hidden) startRender()
})
window.addEventListener('focus', startRender)
window.addEventListener('blur', stopRender)
```

### `prefers-reduced-motion` path

When `window.matchMedia('(prefers-reduced-motion: reduce)').matches`:
- Build the tree normally (same geometry, same particles).
- Render one frame: filaments + particles at their rest positions and base
  alphas, no oscillation.
- Do not call `requestAnimationFrame` for subsequent frames unless a tree
  state change occurs (in which case: cross-fade bloom colour and opacity over
  `--d-1` opacity-only transition; then stop again).
- This is not degradation — it is a first-class designed output.
